# CI/CD Build Dashboard

A Flask application demonstrating a complete, automated CI/CD pipeline: **Git \u2192 GitHub \u2192
Jenkins \u2192 Docker \u2192 Docker Hub \u2192 Kubernetes**, with a live, self-updating dashboard
showing exactly what's deployed at any moment.

## Features

- Fully automated Jenkins pipeline (checkout \u2192 test \u2192 build \u2192 push \u2192 deploy \u2192 verify)
- **Automated test gate** \u2014 pytest suite runs before the Docker image is even built
- **Live self-updating dashboard** \u2014 polls a JSON API every 5 seconds, no page reload
- **Automatic rollback** \u2014 a failed pipeline stage reverts Kubernetes to the last
  working deployment with no manual intervention
- Kubernetes deployment with 3 replica pods for redundancy
- Health-check endpoint (`/health`) used for liveness verification

## Tech Stack

| Layer | Tool |
|---|---|
| Source control | Git, GitHub |
| CI/CD automation | Jenkins (declarative Jenkinsfile) |
| Testing | pytest |
| Containerization | Docker |
| Image registry | Docker Hub |

## Prerequisites

- Docker
- Minikube (or any Kubernetes cluster) + kubectl
- Jenkins with the Docker, Git, and Kubernetes CLI available on the agent
- Python 3 with `pip` and `venv` support
- A Docker Hub account + Jenkins credentials configured under the ID `dockerhub`

## Running Locally (without the pipeline)

```bash
pip install -r requirements.txt
python app.py
# open http://localhost:5000
```

## Running the Full Pipeline

1. Start your cluster: `minikube start`
2. Point Jenkins at this repository (webhook or manual trigger on push to `main`)
3. Trigger a build \u2014 Jenkins will:
   - Check out the code
   - Write fresh build metadata to `build_info.json`
   - Run the automated test suite (`pytest test_app.py`)
   - Build and tag the Docker image
   - Push it to Docker Hub
   - Apply the Kubernetes manifests and roll out the new image
   - Verify pods and service are healthy

See `kubernetes-commands.md` for the full list of kubectl commands used.

## Accessing the Dashboard

If running Kubernetes inside WSL2 (Minikube with the Docker driver), the node IP
isn't reachable directly from a Windows browser. Use port-forwarding instead:

```bash
kubectl port-forward svc/cicd-dashboard-service 5000:5000
```

Then open **http://localhost:5000**.

## Running Tests Manually

```bash
pip install -r requirements.txt
pytest test_app.py -v
```

## Rollback

Rollback is automatic on pipeline failure (see the `post { failure { ... } }` block
in the Jenkinsfile). To roll back manually:

```bash
kubectl rollout undo deployment/cicd-dashboard
```
